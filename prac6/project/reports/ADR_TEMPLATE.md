# ADR-001. Управление приоритетами каскада

**Статус:** принято · **Дата:** 17-18.11.2026

## Контекст

CSS на странице пишут две стороны:

- команда Atlas UI (продуктовая команда): библиотека компонентов и каркас страницы (tokens.css, base.css, components.css, states.css)
- подрядчик: виджет "Согласование закупки" (legacy.css). Удалять его нельзя.

Файл подрядчика подключён без слоя, поэтому его правила сильнее всей библиотеки. В DevTools я видел два конфликта:

1. Кнопка "Основное действие" синяя rgb(41, 57, 168). Правило подрядчика `#workbench .ui-button` лежит вне слоёв и побеждает `.ui-button--primary` из слоя components.
2. Метка "Риск" залита красным. Общий класс `.is-danger` из слоя states побеждает `.ui-tag--danger` из слоя components, потому что states стоит позже.

## Рассмотренные варианты

| Альтернатива | Плюсы | Риски | Почему выбрали или отклонили |
|---|---|---|---|
| A. Всё в одном CSS-файле | Просто, всё в одном месте | Кто ниже в файле, тот и прав. Любая новая строка может сломать чужое. Файл подрядчика всё равно останется отдельным | Отклонили |
| B. БЭМ + регламент селекторов | Понятные имена, у селекторов одинаковый вес | Это только договорённость. От чужого CSS она не защищает: `button {}` и `#workbench` подрядчика всё равно победят. Нет способа делать темы | Берём частично: имена классов в стиле БЭМ |
| C. @layer + токены + контракт компонента | Кто сильнее, решает порядок слоёв, а не вес селектора. Подрядчика можно положить в нижний слой. Темы меняются через переменные. Всё можно проверить тестами | !important в слоях работает наоборот, поэтому его нужно запретить. CSS без слоя сильнее всех, поэтому весь CSS нужно класть в слои | Выбрали |
| D. Только CSS Modules | Имена классов уникальные и не пересекаются | Нужен сборщик, а у нас простой проект без зависимостей. Не помогает против `button {}` и других общих правил подрядчика. Не даёт тем | Отклонили |

## Решение

**Порядок слоёв:** reset, legacy, tokens, base, components, states, utilities. Чем позже слой, тем он сильнее. Что лежит в каждом слое, описано ниже в разделе "Схема слоёв".

**Принцип специфичности:** селектор компонента это один класс, например `.ui-button--danger`. Для состояния можно добавить псевдокласс, например `.ui-button:disabled`. ID в CSS не используем, !important не используем. Общие правила пишем через `:where()`, у него нулевой вес. Если два правила спорят, это решает слой, а не вес селектора.

**Публичные классы и модификаторы:** у каждого компонента есть корневой класс `.ui-*`. Части компонента пишем через `__`, например `.ui-card__meta`. Варианты пишем через `--`, например `.ui-tag--danger`. Состояния берём из HTML: атрибут disabled, `:focus-visible`, `:checked`, `aria-invalid="true"`. Общих классов вроде `.is-danger` нет.

**Зависимость от селекторов родителя:** компонент выглядит одинаково в любом месте страницы. Правил вида `#workbench .ui-button` или `.ui-card .ui-tag` нет. Карточка оформляет только свои элементы: `.ui-card > p`, а не все абзацы внутри себя.

**Третий party CSS:** legacy.css подключается так: `@import url('./legacy.css') layer(legacy)`. Его правила касаются только классов самого виджета (`.legacy-widget`, `.legacy-action`). В нём нет !important, нет ID и нет правил для всех `button` или `input` страницы.

## Последствия и риски

**Если подключится ещё одна команда или библиотека:** она получает свой слой. Если это новый файл подрядчика, его кладём во вложенный слой, например `legacy.v2`. Тогда его обычные правила не смогут перебить библиотеку.

**Риски:**

1. Если кто-то подключит CSS без layer(), он снова станет сильнее всех.
2. Если в слое legacy появится !important, он станет самым сильным правилом.
3. Стили страницы для рамки `.legacy-widget` из base.css теперь сильнее стилей подрядчика. Поэтому рамка виджета станет сплошной, а не пунктирной. Шрифт и кнопка виджета остаются его собственными. Так же выглядит эталон в папке reference.

**Как обнаружить регрессию:**

- `npm test` проверяет порядок слоёв, отсутствие !important и ID, правила подрядчика.
- Playwright проверяет окно, переключатели, форму, ширину страницы и тему.
- В DevTools во вкладке Layers не должно быть правил в "implicit outer layer".
- Скриншоты до и после должны совпадать везде, кроме исправленных мест.

## Два контрпримера

1. **Почему добавление !important не является решением проблемы?** Он прячет проблему, а не убирает её. Чтобы перебить один !important, нужен другой, и так без конца. А в слоях !important работает наоборот: в самом нижнем слое legacy он становится самым сильным, и библиотека его уже не перебьёт.
2. **Где одного @layer недостаточно?** Слой не поможет, если оба правила лежат в одном слое. Например, `.ui-card p` и `.ui-alert p` оба в components, и карточка ломает текст уведомления. Ещё слой не исправит ошибки в JS (окно через show()), в HTML (чекбокс через display: none) и в логике (ошибка поля по :invalid).

## Схема слоёв

| Слой | Файл | Что внутри | Почему здесь |
|---|---|---|---|
| reset | reset.css (создадим на этапе 3) | box-sizing, обнуление отступов | Самая база, всё остальное может её поменять |
| legacy | legacy.css | Виджет подрядчика | Стоит низко, чтобы стили подрядчика не перебивали библиотеку |
| tokens | tokens.css | Переменные цветов, отступов и тем | Только значения, сами по себе ничего не красят |
| base | base.css | body, ссылки, общий фокус, каркас страницы | Общие правила для всей страницы |
| components | components.css | 7 компонентов и их варианты | Обычный вид компонентов |
| states | states.css | hover, focus, disabled, ошибка поля | Состояние должно побеждать обычный вид компонента |
| utilities | utilities.css | Маленькие помощники, например `.u-visually-hidden` | Должны срабатывать всегда, поэтому это самый сильный слой |

## Контракт компонентов

| Компонент | Класс | Части | Варианты | Состояния |
|---|---|---|---|---|
| Кнопка | `.ui-button` | нет | `--primary`, `--secondary`, `--ghost`, `--danger`, `--sm`, `--lg` | hover, active, focus-visible, disabled |
| Поле | `.ui-field` | `__hint`, `__actions` | `--full` | ошибка (`aria-invalid="true"`), focus-visible |
| Карточка | `.ui-card` | `__meta` | `--featured` | нет, карточка не кликается |
| Метка | `.ui-tag` | нет | `--neutral`, `--success`, `--warning`, `--danger` | нет, метка не кликается |
| Уведомление | `.ui-alert` | `__dismiss` | `--info`, `--success`, `--warning`, `--danger` | кнопка закрытия с focus-visible |
| Переключатель | `.ui-switch` | `__copy`, `__track`, `__thumb` | нет | включён (checked), focus-visible, disabled |
| Окно | `.ui-dialog` | `__head`, `__actions` | нет | открыто модально (showModal), закрывается по Escape |

## Правила, которые проверяют тесты

1. Порядок слоёв записан в app.css (тест 01).
2. legacy.css подключён в слой legacy (тест 02).
3. Нигде нет !important (тест 03).
4. Окно открывается через showModal() (тест 04).
5. У кнопки и переключателя есть focus-visible (тест 05).
6. Чекбокс переключателя не скрыт через display: none (тест 06).
7. В компонентах нет кодов цветов, только переменные (тест 07).
8. Нет общего класса .is-danger (тесты 08 и 17).
9. Ошибка поля показывается по aria-invalid (тест 09).
10. Нет min-width 20rem и 22rem (тест 10).
11. У кнопки один базовый блок .ui-button (тест 11).
12. Есть режим reduced-motion (тест 12).
13. Нет :is() с ID внутри (тест 13).
14. Правила подрядчика не трогают библиотеку и теги страницы (тест 18).
